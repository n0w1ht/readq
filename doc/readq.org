# The source of the manual that C-h R readq shows.  After editing it,
# run `make info' to rebuild readq.texi and readq.info.

readq keeps a queue of everything you are reading through (books,
lecture recordings, web pages) and tells you what to read next.  It
remembers where you stopped in each one.  Passages worth keeping become
*extracts*, short notes that come back for review until you turn them
into flashcards.

The routine is always the same:

1. ~C-c r n~ opens what you should read now.
2. Read for a while.  Select a passage worth keeping and press ~C-c r e~.
3. ~C-c r n~ again.  readq saves your place and opens the next item.

This manual shows how to do each part.  It uses ~C-c r~ as readq's
prefix key.  In Emacs, open it with ~C-h R readq~ or ~C-c r h~; in it,
~i~ looks up a command or option by name and ~s~ searches the text.

* Getting started

** Installing
#+findex: readq-mode
#+vindex: readq-mode

readq is a folder of Emacs Lisp files.  It needs Emacs 27.1 or later,
and two small packages of the same author: [[https://github.com/n0w1ht/card-export][card-export]] and [[https://github.com/n0w1ht/readq-comic][readq-comic]].
Put all three folders on your load path:

#+begin_src emacs-lisp
(use-package readq
  :load-path ("~/src/card-export" "~/src/readq-comic" "~/src/readq")
  :config (readq-mode 1)
  :bind-keymap ("C-c r" . readq-command-map))
#+end_src

=readq-mode= is what follows you as you read: it brings each book
back to your place and counts your reading time.

Everything else is optional.  Install only what you read with:

| To read                  | Install                                        |
|--------------------------+------------------------------------------------|
| PDFs                     | pdf-tools (or pdf-canvas, or use =doc-view=)   |
| EPUBs                    | nov.el                                         |
| Audio, video, YouTube    | mpv, and yt-dlp for online videos              |
| Comics                   | 7-Zip, unar, or unzip for CBZ only             |
| PDFs outside Emacs       | SumatraPDF (Windows)                           |
| Fast extract search      | consult and ripgrep                            |
| Flashcards               | org-srs, or Anki with the AnkiConnect add-on   |
| Reading aloud            | kokoro.el                                      |

** Checking your setup
#+findex: readq-doctor

Run ~C-c r ?~ (=readq-doctor=) once after installing, and again
whenever something stops working.  It checks every program readq uses
and says how to fix what is missing:

#+begin_example
ok  Database    ~/notes/readq.eld: 42 books, 310 extracts
ok  pdf-tools   epdfinfo works
XX  nov.el      cannot find unzip (`nov-unzip-program')
--  Anki        AnkiConnect does not answer; start Anki before exporting
#+end_example

=XX= is a problem with something you use, =!!= a warning, =--= a note
about something you don't use yet.  Press ~g~ to check again.

** Your first ten minutes
#+findex: readq-add-book
#+findex: readq-add-directory
#+findex: readq-next
#+findex: readq-extract
#+findex: readq

1. ~C-c r a~ adds a file.  Give it a priority from *0 (most important)
   to 100 (least)*, and tags if you like, such as =cardio=.  ~C-c r A~
   adds every book in a folder.
2. ~C-c r n~ opens the book to read now.  Read a few pages.
3. Select a sentence worth keeping and press ~C-c r e~.  It is now an
   extract.
4. ~C-c r n~ again.  Your place is saved and the next item opens.
5. ~C-c r l~ shows the whole queue.

You can also open a queued file the usual way, with ~C-x C-f~ or Dired:
readq recognizes it and puts you back where you were.

* Reading every day

** The daily loop
#+findex: readq-next
#+findex: readq-finish-session
#+findex: readq-open
#+findex: readq-suggest
#+findex: readq

| Key         | What it does                                                   |
|-------------+----------------------------------------------------------------|
| ~C-c r n~   | finish what you are reading and open the next due item        |
| ~C-u C-c r n~ | the same, but only from some tags (e.g. only =#cardio=)     |
| ~C-c r f~   | finish the session without opening anything                    |
| ~C-c r o~   | open an item you choose                                        |
| ~C-c r s~   | list what is due today, without opening anything               |
| ~C-c r l~   | the dashboard: the whole queue                                 |

A session counts, and the item is scheduled again, if you moved forward
or read for at least a minute.  Just glancing at a book changes nothing.

When you reach the end of a book, readq offers to mark it finished.

** How often things come back
#+findex: readq-set-priority
#+findex: readq-priority-up
#+findex: readq-priority-down

Priority decides it.  *Lower numbers come first and come back sooner.*

- *Books, chapters and recordings* come back at a steady rhythm: every
  day at priority 0, about once a week at priority 100.
- *Extracts* come back after growing gaps: a few days, then weeks, then
  months.  The less important, the faster the gap grows.

Change a priority with ~C-c r =~, or nudge it with ~C-c r +~ and
~C-c r -~.  It is the main thing you tune.

** When it gets too much
#+findex: readq-next
#+findex: readq-postpone
#+findex: readq-reschedule
#+findex: readq-toggle-pause
#+findex: readq-toggle-finished
#+findex: readq-workload

readq plans each day up to a *budget*, 90 minutes by default.  What
doesn't fit moves to the next days, least important first.  Items of
priority 10 or lower always stay.  Once the budget is used up, ~C-c r n~
asks before opening more.

#+begin_src emacs-lisp
(setq readq-daily-minutes 60)   ; or nil for no limit
#+end_src

For one item at a time:

| Key       | What it does                                   |
|-----------+------------------------------------------------|
| ~C-c r z~ | postpone it (~C-u~: by a number of days)        |
| ~C-c r r~ | read it again in N days                         |
| ~C-c r x~ | pause it until you press ~x~ again              |
| ~C-c r F~ | mark it finished (or not)                       |
| ~C-c r L~ | see today's budget and the load of the next days |

** Deadlines and exams
#+findex: readq-set-deadline
#+findex: readq-review-subset
#+findex: readq-focus
#+findex: readq-set-tags
#+findex: readq-exam
#+findex: readq-workload

- ~C-c r !~ sets a date by which to finish a book or chapter.  readq
  works out the pace per day and keeps it coming back often enough.
  A deadline beats the daily budget.
- ~C-u C-c r !~ sets a deadline for a whole tag, such as =#cardio=.
- ~C-c r b~ reviews one book, chapter, extract or tag *now*, due or
  not: the cram before an exam.  ~C-c r n~ goes through it in order;
  ~C-u C-c r b~ stops.
- ~C-c r /~ sets a *focus*: until you clear it, only items with those
  tags are suggested.  ~C-c r #~ sets an item's tags.

*Exam mode.*  ~C-c r t~ asks for an exam's name, its date and the tags it
covers, and plans back from the date:

1. /Reading/, until ten days before: everything with those tags gets
   that day as its deadline, so readq sets the pace.
2. /Extracts only/, for the next seven days: the exam's books stay
   closed and each of its extracts comes up at least once.  Turn them
   into cards.
3. /Cards only/, for the last three days: nothing of the exam comes up
   in readq.  Review your cards.

Over the last two weeks the daily budget grows, to one and a half
times on the day.  ~C-c r L~ shows where each exam stands.  To drop an
exam, press ~C-c r t~, choose it and give no date.  The lengths are
~readq-exam-extract-days~, ~readq-exam-card-days~, ~readq-exam-ramp-days~
and ~readq-exam-budget-factor~.

** The dashboard
#+findex: readq
#+findex: readq-stats

~C-c r l~ shows the queue as a tree: chapters and extracts under their
book, sub-extracts under their extract.  Rows are in the order you
should read them.  The mode line sums it up, for example
=3 due (1 extracts), 40 in queue — today 52/90 min=.

The dashboard uses the same letters as ~C-c r~ (=, z, x, #, b, L...),
on the row at point.  A few are its own:

| Key           | What it does                                  |
|---------------+-----------------------------------------------|
| ~RET~         | open the item, or fold a chapter              |
| ~TAB~ / ~S-TAB~ | fold this row / all rows                    |
| ~N~           | read next                                     |
| ~t~           | rename the item                               |
| ~l~           | point it to its file again, after you moved it |
| ~D~           | remove a book from the queue                  |
| ~.~           | show or hide extracts                         |
| ~H~           | show or hide finished books                   |
| ~G~           | redraw                                        |

~C-c r %~ shows reading stats: minutes per day, streak, pages, and
time by book and tag (~w~, ~m~, ~y~ for week, month, year).

* Books

** What readq can read
#+findex: readq-add-url

| File                           | Read in                         | Your place is   |
|--------------------------------+---------------------------------+-----------------|
| PDF                            | pdf-tools, pdf-canvas, doc-view, or SumatraPDF | the page |
| EPUB                           | nov.el                          | the spot in the chapter |
| Org, Markdown, text            | any mode                        | the spot, found again by its words |
| HTML                           | eww                             | the spot        |
| Comics (CBZ, CBR, CB7)         | readq's viewer, or SumatraPDF   | the page        |
| Audio and video                | mpv                             | the time        |
| YouTube and other sites        | mpv with yt-dlp (~C-c r u~ to add) | the time     |

** One chapter at a time
#+findex: readq-add-sections

A big textbook works better as chapters, each its own item with its
own priority.  Press ~C-c r T~ on the book: readq lists its table of
contents.  Mark the chapters you want with ~m~ (or ~=~ to give one its
own priority), then press ~x~ to add them.  readq offers to pause the
book itself, so only the chosen chapters come up.

A chapter keeps its own place; reading it doesn't move the book's
bookmark.  For a PDF without bookmarks, =M-x readq-add-section= adds a
chapter by its page numbers.

** PDFs in SumatraPDF
#+vindex: readq-default-pdf-viewer
#+findex: readq-set-viewer

On Windows you can read a PDF or comic in SumatraPDF instead of Emacs:
~C-c r v~ switches the item at point, and =readq-default-pdf-viewer=
sets it for all.  readq opens SumatraPDF at your page, and learns the
new page when you *close the document*.  Highlights you save into the
PDF there become extracts (see [[*Highlights from other PDF viewers]]).

** Lectures and videos
#+findex: readq-add-book
#+findex: readq-add-url
#+findex: readq-add-sections
#+findex: readq-set-media-toc

- ~C-c r a~ adds a recording; ~C-c r u~ adds a YouTube link.
- ~C-c r n~ plays it in mpv from where you stopped.  Quit mpv with ~q~
  and your time is saved.
- In mpv, ~Ctrl+b~ marks the moment as an extract, and ~Ctrl+f~ saves
  the frame as a figure.
- Chapters of a recording can be read as sections with ~C-c r T~.  If
  it has none, select a chapter list (from a YouTube description, say)
  in any buffer and press ~C-c r M~.

** Listening with Kokoro
#+findex: readq-read-aloud
#+findex: readq-save-extracts-audio

With kokoro.el installed:

- ~C-c r R~ reads the book aloud from your bookmark, or the extract
  you are reviewing.  Listening counts as reading time.
- ~C-c r V~ saves today's due extracts as one audio file, for a walk.
  With ~C-u~, those of one book, chapter or tag.

* Extracts

** Making an extract
#+findex: readq-extract

Select the passage and press ~C-c r e~.  That works in pdf-tools,
pdf-canvas, nov.el, eww, Org, Markdown and text, and inside an extract
(which makes a *sub-extract*).  In a PDF, the passage is also
highlighted and saved into the file.  ~C-u C-c r e~ asks for a priority.

Several passages at once: in a PDF, drag with ~C-~ held for each; with
the multi-region package, any selection it holds.  They become one
extract (~C-u C-u C-c r e~: one each).

** Highlight, keep or review
#+findex: readq-highlight
#+findex: readq-extract-keep
#+findex: readq-extract
#+findex: readq-find-highlight
#+findex: readq-toggle-finished
Not every passage deserves a place in the queue.  Select it, then:

| ~C-c r H~ | *highlight* it and nothing more                              |
| ~C-c r K~ | make an extract that is *kept* as a note but never comes up |
| ~C-c r e~ | make an extract that comes back for *review*                |

A highlight in a PDF is saved into the PDF, in green; in an EPUB, a
text or a web page, readq remembers it and shows it when you read
there.  ~C-c r J~ lists the highlights of a book and jumps to one;
~C-u C-c r H~ on a highlight removes it.

You can change your mind later.  On a highlight, with nothing selected,
~C-c r e~ or ~C-c r K~ makes it an extract.  On a kept extract, ~C-c r F~
puts it in the queue.

** Reviewing extracts
#+findex: readq-goto-source
#+findex: readq-open
#+findex: readq-edit-extract
#+findex: readq-dismiss
#+findex: readq-mark-ready

When ~C-c r n~ brings up an extract, it opens its note.  Then:

- *Shorten it.*  Delete what you don't need and rewrite the rest.  Each
  review boils it down a little.  This is the heart of incremental
  reading.
- ~C-c r e~ on part of it makes a sub-extract.
- ~C-c r g~ shows the passage in the book.  Your bookmark stays where it
  was; ~C-c r o~ goes back to it.
- ~C-c r '~ edits the extract in a window beside the book.
- ~C-c r d~ dismisses it: out of the queue, note kept.
- ~C-c r c~ marks it ready for a flashcard (see [[*Flashcards]]).
- ~C-c r n~ moves on.

** Where extracts are stored
#+vindex: readq-extracts-directory
#+findex: readq-visit-extracts

Each extract is one Org file in =~/notes/=, named the way [[https://protesilaos.com/emacs/denote][Denote]] names
notes, so Denote, consult-notes or plain Dired all work with them:

#+begin_example
20261115T142233==guyton=physiology=p0057--systole-is-the-phase__cardio_extract.org
#+end_example

#+begin_src org
,#+title:      Systole is the phase of contraction.
,#+filetags:   :cardio:extract:
,#+identifier: 20261115T142233
,#+signature:  guyton=physiology=p0057
,#+source:     [[readq:20261115T142233][Guyton Physiology, p. 57]]

,#+begin_quote
Systole is the phase of contraction.
,#+end_quote
#+end_src

The title can be anything; edit it and the file is renamed.  ~C-c r E~
lists a book's notes in Dired, in book order.  To keep them elsewhere,
set =readq-extracts-directory=.

Coming from readq 0.1?  =M-x readq-convert-extracts= turns your old
extracts into notes like these.  The old files are left alone.

** Figures
#+findex: readq-extract-figure
#+findex: readq-extract-figure-from-clipboard

~C-c r P~ makes a diagram or picture an extract.  In a PDF, select the
area with ~M-drag~ first; in an EPUB, web page or Org file, put point on
the image; in a comic, it takes the page.  Pictures copied elsewhere
(SumatraPDF, a browser) are taken from the clipboard with ~C-c r y~.

Figures are saved in =~/notes/figures/= and shown in the extract.  They
go to Anki and org-srs with the card.

** Finding an extract
#+findex: readq-search
#+findex: readq-find-extract
#+findex: readq-visit-extracts

| Key       | What it does                                              |
|-----------+-----------------------------------------------------------|
| ~C-c r S~ | search the text of all extracts as you type (consult)     |
| ~C-c r j~ | pick an extract from a list, by book, text or tag         |
| ~C-c r E~ | a book's extracts in Dired                                |

** Cleaning up
#+findex: readq-stale-extracts
#+findex: readq-delete-extract
#+findex: readq-dismiss

Extracts you keep postponing pile up.  ~C-c r X~ walks through the
*stale* ones, reviewed often or long ago without becoming anything, and
asks for each: make it a card, merge it into another, dismiss, delete,
or keep.

~C-c r D~ deletes an extract with its note and its highlight in the
PDF.  ~C-c r d~ only takes it out of the queue.

** Highlights from other PDF viewers
#+findex: readq-import-highlights
#+findex: readq-import-all-highlights

Highlights saved into a PDF by SumatraPDF, Okular or a tablet app
become extracts: ~C-c r i~ for the book at point, ~C-c r I~ for all PDFs.
readq also looks for new ones before suggesting what to read.  Needs
pdf-tools.

* Flashcards
#+findex: readq-cloze
#+findex: readq-mark-ready
#+findex: readq-export-cards
#+findex: readq-update-anki-cards

Once an extract holds just one fact, make it a card:

1. *Shape it.*  For a cloze, select the words to hide and press
   ~C-c r k~ (~C-u~ adds a hint).  Otherwise the extract's *title is the
   question* and its text the answer: rewrite the title as a question.
2. *Mark it ready* with ~C-c r c~.  It leaves the reading queue.
3. *Export* all ready extracts with ~C-c r C~.

readq asks where to send them, or set it once:

#+begin_src emacs-lisp
(setq readq-flashcard-backend 'anki)   ; or 'org-srs
#+end_src

- *Anki:* keep Anki open with the AnkiConnect add-on (code
  =2055492159=).  Cards go into the deck =readq::<book>=.  If you edit an
  extract later, ~C-c r U~ updates its card and keeps its reviews.
  Without AnkiConnect, readq writes a file for /File > Import/.
- *org-srs:* cards go into =<book>-cards.org= next to your notes.  Review
  them with =M-x org-srs-review-start=.

** Drafts from a local model
#+findex: readq-draft-cards
#+findex: readq-mark-ready
If you use gptel, ~C-c r Q~ on an extract asks its model for three card
drafts, clozes and questions, from the extract's text.  Choose one: it
is written into the note for you to correct, then ~C-c r c~ as usual.
The text goes only to the model gptel is set up with, so with a local
model nothing leaves your computer.  Drafts can be wrong: check them
against the passage.  ~readq-draft-count~ and ~readq-draft-instructions~
change what is asked.

** Cards you keep failing
A card failed three times was learned without its context.  Its
extract then comes back into the reading queue, due today, and opens
with the passage in the book beside it: reread, rework the extract,
~C-c r n~.  With org-srs, readq counts each "again".  With Anki, it asks
once a day while Anki is running (=M-x readq-check-failed-cards= asks
now).  ~readq-card-lapse-threshold~ sets the number; =nil= turns it off.

* Your data
#+findex: readq-restore-backup

Everything readq keeps is in =~/notes/=:

| File               | Holds                                         |
|--------------------+-----------------------------------------------|
| =readq.eld=        | the queue: priorities, dates, places, history |
| =readq-backups/=   | a copy of the queue from each of the last 14 days |
| =*__extract.org=   | your extracts, one note each                  |
| =figures/=         | the pictures of figure extracts               |

Back up the whole folder.  If the queue file is ever damaged, ~C-c r B~
puts back a daily copy.  The queue file is plain text, so it syncs well,
but don't run readq on two computers at the same time.

* When something goes wrong
#+findex: readq-mode
#+vindex: readq-mode
#+vindex: readq-mpv-program
#+vindex: readq-daily-minutes
#+findex: readq-doctor

Start with ~C-c r ?~.  It finds most problems and says what to do.

- *A book doesn't open at my place.*  Is =readq-mode= on?  Did the file
  move?  Then press ~l~ on it in the dashboard to point readq to the new
  place.
- *SumatraPDF doesn't save my page.*  readq learns it when you close
  the document in SumatraPDF.  Keep its option /Remember opened files/
  on.
- *mpv doesn't start.*  Check that =mpv= runs in a terminal, or set
  =readq-mpv-program=.  For YouTube, update yt-dlp.
- *Anki export fails.*  Open Anki first, with AnkiConnect installed.
- *A figure shows as a link.*  Press ~C-c C-x C-v~ in the note to show
  images.
- *Too much is due.*  Lower the priority of what matters less, pause
  books you are not reading now (~x~), or lower =readq-daily-minutes=:
  readq spreads the rest.

[[https://github.com/n0w1ht/readq/issues][the issue tracker]].
